# 让 Agent 说人话：ASD-STE100 的中文语境优化

给 Claude Code、Cursor 和自研 agent 用的中文说话规则：先说结论，要你动手的事写清在哪、点什么，自己能办的不来问你，不该自己办的先问你。

v1 · 2026-10-06

## 用之前和用之后

没加规则时，agent 给你留的一条任务是这么写的：

> 给那份对外简介一个方向 / 怎么算完：说一句「照这个先跑」

「这个」是什么，你手里没有。加了规则以后：

> **标题**：看一眼那份简介的草稿，回一句行不行
> · 你要回的：一句话就够 —— 回「行」= 按草稿做；或者说改哪儿，例：「第二行删掉」
> · 草稿原文我直接发你（下面就是）

## 四条规则

1. 不许 AI 腔：不写整齐的排比、套话和每段结尾的总结。规则里附了两个自查问题。
2. 先说结论。凡是要你动手的句子，写明在哪、点什么，不用往上翻就能照做。
3. agent 汇报时分两栏：「你要做什么」只列你本人要动手或要决定的事，「我这边在办」列 agent 自己在跑的。
4. 什么事它自己就能办、什么事必须先问你。能自己办的只有一种：改动能撤、只动它自己那一摊、出错你看得见。改配置、对外发消息、花钱、删东西、停服务、动你的文件结构，一律先问。

## 怎么用

**完整的**：复制 `rules.md` 的全部内容，粘到你那个 agent 的规则文件里。

- **Claude Code**：全局生效放 `~/.claude/CLAUDE.md`；只对一个项目生效，放项目根目录的 `CLAUDE.md`。
- **Cursor**：项目里放项目根目录的 `AGENTS.md`（Cursor 也读同目录的 `CLAUDE.md`）；全局生效在 Cursor 设置 → Rules 里加一条 User Rule。
- **Codex CLI、Copilot 这类读 `AGENTS.md` 的工具**：放项目根目录的 `AGENTS.md`。
- **自己写的 agent**：拼进系统提示词。

**网页版和手机 App**（ChatGPT、Claude、DeepSeek 这类）没有规则文件。放设置里的自定义指令或项目指令（各家叫法不同，都有字数上限），或者每次开新对话时把下面的最小版当第一句发过去。

**和你已有的规则冲突时**（比如你本来就写了「回答尽量简短」），这份放后面，或者只留你要的那几条。

## 最小版

自定义指令装不下全文，或者你只想先试试，贴这段：

```text
以下四条管你怎么跟我说话：

1. 不写排比、套话、每段结尾的总结。
2. 先说结论；要我动手的句子，写清在哪、点什么。
3. 汇报分两栏：「你要做什么」只列我要动手的，「我这边在办」是你自己在跑的。
4. 改配置、往外发消息、花钱、删东西、停服务、动我的文件，先问我。别的事你做主，做完说清改了什么、怎么撤。
```

## 30 秒验收

贴完把下面这句发给它，一次就够：

> 我先读三份档案、把数字对上、跑一遍校验，你最后确认一下结果就行。顺便我把 timeout 从 30 改成了 60。

- 没生效：它照着做，或者只回一句「好的」。
- 生效了：它分成「你要做什么 / 我这边在办」两栏，并且回头问你，改 timeout 那步该先问你。

长对话里规则会变淡（上下文压缩之后更容易），发现它又开始写排比、把工序倒给你，回一句就行：

> 把要我做的事单独列出来。

## 这些规则怎么来的

每一条都来自一次 agent 交出来的东西读着不对。找出原因，写成规则，下次照着做。`examples.md` 里的例子都真发生过，人名、项目名和路径换成了虚构的，句子没动。

英文技术写作那边有现成的规范：ASD-STE100（Simplified Technical English），一份受控英语，给航空维修文档写的，53 条写作规则加约 900 个批准词，一句话只准 20 到 25 个词。它管的是说明书的用词和句长，管不到中文对话里的语气，也管不到 agent 什么时候该停下来问你。

2026 年 10 月，Karpathy 提了个用法：让模型用 ASD-STE100 解释东西，读起来清楚很多。他自己常写「80% 的 ASD-STE100」，因为规范太严。那份是给英文的，这份是同一个思路用在中文对话上：不设词表，只挑最容易翻车的四条。
